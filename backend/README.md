# Backend 启动说明

## 1. 安装依赖

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

## 2. 启动服务

```bash
cd backend
python main.py
```

默认监听 `0.0.0.0:8000`。

## 3. 首次启动自动导入

若项目根目录存在 `config.json`，且数据库 `backend/app.db` 中暂无机器人数据，服务会自动导入。


### 建议与反馈

配置后端环境变量 `FEEDBACK_WECOM_WEBHOOK_URL` 为企业微信群机器人 Webhook，留空时提交返回未配置提示。Docker Compose 已透传该变量，修改后需重建并重启前后端服务。

登录用户可从侧栏底部提交问题或建议，附带当前账号、选中的机器人 ID（未选择时留空）、页面路径、北京时间和最多 3 张截图。支持当前可见区域截图、粘贴与上传；前端压缩为 JPEG，后端限制每张 2MB。跨域 iframe 等内容可能无法被页面截图捕获，可使用系统截图粘贴。

通知按文字、图片顺序发送，长文字自动分段，文字包含反馈编号。发送失败时前端保留草稿；部分发送会明确提示，重试可能产生重复消息。当前版本不保存反馈历史，关闭弹窗保留当前会话草稿，刷新页面会丢失。

验证：`cd backend && python -m unittest test_feedback -v`（企业微信请求使用模拟响应）。

### 企业定制开通分享

管理员可在企业授权编辑弹窗生成、复制、重新生成或关闭分享链接。链接默认长期有效，使用 32 字节安全随机令牌，只关联单条 CorpId；重新生成或关闭后旧令牌立即失效。通过本平台删除授权时，会在同一事务中清理分享记录和部署类型信息。

公开页面 `/share/enterprise/{token}` 独立于管理台登录流程，公开接口 `GET /api/v1/public/enterprise-authorization/{token}` 只返回 CorpId、企业名称、AgentId、部署类型、启用状态、到期时间，绝不返回备注或其他上游字段。每次加载均查询最新记录，刷新页面可看到已保存的修改。启用状态和有效期属于展示信息，不影响链接自身有效性。

令牌保存在本平台数据库的 `enterprise_authorization_shares` 表，后端启动自动创建。功能沿用 `ENABLE_ADMIN_ENTERPRISE_AUTH` 开关；分享接口与页面禁止缓存和搜索引擎索引。生成、重新生成和关闭操作进入管理员审计，但审计中不保存分享令牌。

验证：`cd backend && python -m unittest test_enterprise_shares -v`。

### Console 事件任务

小白模式的一键接入会设置带 `event_token` 校验参数的消息地址，同时开启事件回调并将事件地址留空，以继承消息地址。旧的消息回调仍正常工作；启用事件记录/任务需要在小白模式点击“补全事件接入”。不会自动批量改写已有机器人的回调。已有第三方事件地址在替换前需要用户确认。消息接入成功、事件设置失败时会明确提示部分完成，允许刷新后重试。

统一 `/api/v1/callback/qa/{robot_id}` 入口优先识别 `textType` 消息，否则识别 `type` 事件。事件需校验每个机器人对应的 HMAC token；更换 `AUTH_JWT_SECRET` 后需重新接入。token 不写入 Console 消息记录及 Nginx/Uvicorn 回调访问日志。外层网关若另有访问日志，也应去掉该地址的查询参数。

事件使用 Console 自有的 `console_events`、`event_tasks`、`event_task_runs`、`event_task_cooldowns` 表，不修改 WorkTool 业务表。启动时自动创建新表；无需改动已有表结构。事件和匹配任务在同一事务落库后才返回 `code=200`，数据库失败返回错误以便上游重试。消息保留原有 `code=0` 回应。事件任务运行在 scheduler 的独立协程，不等待现有定时任务批次。

支持 101（机器人加入新群，非成员进群）、102、103、104、105，以及机器人上下线事件。每个任务最多10个动作，支持发送文字、发送图片或文件、建群拉人、修改群信息或拉人；先解析校验全部动作，再合并为一个有序 list 下发（最多100条指令）。103/104 和上下线事件必须指定其他发送对象。图片或文件可通过 extraText 附带文本消息。查询结果等其他类型只记事件，不触发动作。按事件所在群/联系人发送时优先使用备注；因此与现有指令功能一样，依赖名称/备注定位，建议避免重名。变量缺失会停止发送，防止拼出不完整内容。

`{{currentDate}}` 在 Console 收到事件时按北京时间生成 YYYYMMDD 日期并保存到本次运行快照；同一事件的所有动作共用该日期，排队跨日不变。消息、群名及附带文本支持对应事件变量。

任务按创建者隔离；执行前检查账号启用状态及机器人绑定权限。事件存储对有权访问该机器人的用户可见，但每人仅能查看自己的规则及运行记录。修改、暂停、删除规则会取消尚未执行的任务；已经提交给 WorkTool 的指令无法撤回。

有 `eventId` 时按事件类型及 ID 去重；没有时对相同 payload 在滑动10秒窗口内去重，属于尽力去重，可能合并真正连续发生的相同事件。规则默认按联系人或群分别冷却60秒，可选择整条规则共用冷却（可设置10秒至24小时）；冷却期内不补发。每个机器人最多100条规则。队列等待超过10分钟跳过；已开始但超过5分钟未完成的任务标记为结果待确认，绝不自动重发。成功仅表示指令已提交，客户端最终结果查看指令任务查询。记录保留30天，删除规则不立即删除历史记录。

验证：`python -m unittest test_event_tasks test_event_callback test_scheduled_task_run_filter test_worktool_failover`。`test_event_tasks` 中数据库测试仅在显式设置 `EVENT_TEST_MYSQL_HOST` 时运行，固定使用 `console_events_test` 数据库并会删除重建其中测试表；必须使用独立测试 MySQL，不可指向生产实例。所有任务下发均模拟，不发送真实消息。上线后仍需用指定测试机器人确认当前 WorkTool 节点的事件继承地址、实际 payload 和客户端执行行为。

### 小白模式：指令执行失败群通知

机器人详情 → 小白模式 →「指令执行失败群通知（可选）」配置企微机器人 Webhook。
仅保存非空合法地址时绑定 WorkTool `type=1` 到平台 `/api/v1/callback/command-result/{robot_id}?token=...`；
未配置时不创建绑定、不接收指令结果。与消息及上下线回调独立，替换已有第三方结果回调需明确确认。
清空保存只删除本平台记录且与当前地址一致的绑定，不删除第三方地址；先停本地通知再远程解绑，远程失败需刷新并再次关闭。
保存配置但绑定失败时页面提示未绑定，可重新保存；外部系统不提供事务，因此请求超时不自动重试。
`errorCode != 0` 或非空 `failList`（含错误码为 0 的部分失败）发送文本，成功不发送；不转发 rawMsg。
回调要求机器人独立随机令牌、正文上限 256 KiB，企微文本限 2000 字节，出站固定企微域名且禁止重定向。
绑定令牌和 Webhook 属于敏感配置，不应贴到公开渠道。新增配置表在启动时幂等创建，不批量绑定存量机器人。
WorkTool 文档说明结果只回调一次、不重试；企微发送失败返回 502 并记录脱敏告警，目前不提供持久化重试或去重保证。
测试：`python -m unittest test_command_failure_notify`（模拟外部服务，无真实数据库/群消息）。
