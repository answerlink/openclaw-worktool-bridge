# 机器人与回调

## 添加与选择机器人

在「机器人配置」添加机器人 ID，后续在各页面选择要操作的机器人。多台机器人配置前先核对选择框，避免改错对象。

同一机器人可能被多个账号绑定。解绑只解除当前账号的关联，不等于删除机器人或清空它的共享配置。不同账号对同一机器人的配置可能互相影响。

## 快速接入 Console

打开「机器人信息」的「机器人使用设置」：

- 首次接入使用小白模式的「一键接入平台」。
- 消息已接入但事件尚未接入，使用「补全事件接入」。
- 已有其他业务地址时，查看覆盖确认后再决定是否更换。

请保留平台生成的完整 URL，包括查询参数。事件接收地址中的签名参数也是地址的一部分，不要自行删改。

## 各类回调如何选择

| 配置 | 接收什么 | 常见用途 |
| --- | --- | --- |
| 消息回调 | 群聊、私聊消息 | Console 自动回复与消息转发 |
| 事件回调 | 入群、群改名、通过好友申请等事件，以及在线状态 JSON | Console 事件记录与事件任务 |
| 执行结果回调 | 指令执行结果 | 第三方跟踪指令完成情况 |
| 群二维码回调 | 群二维码结果 | 第三方保存或展示二维码 |
| 上线、下线通知 | 独立在线状态通知，兼容企微 webhook | 直接通知运维人员 |

在线状态既可走独立通知，也可走事件回调；同时配置时两边都收到属于预期行为。

事件回调地址留空时沿用消息回调地址，填写独立地址则投递到该地址。填写地址之外，还要确认对应开关已开启。要让 Console 处理事件，事件最终接收地址必须指向 Console；仅开启开关并不能把投递到外部系统的数据同步到这里。

## 接入后怎么验收

1. 发一条新消息，在「消息监控」查看消息记录。
2. 做一次真实的新事件，例如测试群改名，在「消息监控 → 事件记录」查看。
3. 若配置了事件任务，再看任务的运行记录和指令执行结果。

「事件任务」列表展示的是你创建的自动化规则，不是已收到的事件。未创建任务时列表为空，不代表没收到事件。

测试回调用于验证接收地址与响应；HTTP 200 不能单独证明真实客户端事件已生成、被正确分类，或动作已执行。

## 地址和网络

回调接收端需能被实际发送方访问。客户端直发的数据需要手机网络可访问；由 WorkTool 服务投递的数据需要服务端可访问。独立部署应分别检查这些网络路径。

图片等大数据可能根据部署配置走不同投递路径。不要把普通事件的接入成功当成图片链路也已验证。

更多结果核对方法见[消息监控与排障](/docs/monitoring.html)。
