# 快速开始

本流程先验证一台机器人、一条消息，确认整条链路可用后再配置更多自动化。

## 1. 添加机器人

登录 Console，打开「机器人配置」，添加你的机器人 ID。确认所选机器人与安卓端保存的 ID 一致，并查看在线情况。不要把用于演示的机器人当成自己的生产机器人。

## 2. 将回调接入 Console

进入「机器人信息」，选择该机器人，在回调配置的小白模式中使用「一键接入平台」。如果消息已接入而事件尚未接入，使用「补全事件接入」。

接入会修改该机器人的回调配置。已有第三方回调时，先看清页面展示的当前地址与覆盖确认，避免替换仍在使用的业务接收端。需要自定义地址时，见[机器人与回调](/docs/robot-callback.html)。

## 3. 准备回复引擎

在「AI回复引擎」新增引擎，填写服务地址、凭证及所需模型，运行接口测试。也可用页面提供的模拟引擎验证链路；它返回固定文本，不代表真实模型能力。

## 4. 开启一个回复场景

在「机器人配置」开启私聊回复或群聊回复，添加规则并选中引擎。初次测试可在专用测试会话中配置全部匹配。群聊建议先选「只有 @ 机器人时回复」。

规则中的名称与内容当前采用“任一命中”逻辑，不能当成同时满足的限制条件。正式配置前阅读[规则匹配说明](/docs/rules.html)。

## 5. 发消息并检查结果

1. 在企业微信测试会话发一条新消息；群聊按配置 @ 机器人。
2. 到「消息监控」查看是否收到消息、是否跳过、是否调用引擎。
3. 回到企微确认实际收到回复；需要核对指令结果时查看「指令任务查询」。

接口测试成功只验证引擎接口；手机收到回复才证明这一条完整链路成功。

## 6. 添加自动化

- 定期执行：配置[定时任务](/docs/scheduled-tasks.html)。
- 发生指定事件后执行：配置[事件任务](/docs/event-tasks.html)。
- 收到文字后转发：配置[消息转发](/docs/forwarding.html)。

若没有收到任何消息或事件，按[排障顺序](/docs/monitoring.html)检查，先解决接入，再调整规则。
