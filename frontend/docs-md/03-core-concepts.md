# 核心概念

## 各部分负责什么

| 名称 | 作用 |
| --- | --- |
| 安卓客户端 | 读取企微页面、执行发消息和群操作等动作 |
| WorkTool 服务 | 管理机器人连接、指令和回调 |
| Console | 提供配置页面、规则、AI 接入及自动化任务 |
| 回调 | 将消息、事件或结果推送到指定接收地址 |
| 回复引擎 | 根据规则处理输入；模型引擎生成回复，回调类型引擎把处理交给第三方 |

机器人 ID 用于关联这些部分。Console 中的显示名称便于识别，不会替代机器人 ID。

## 消息、事件和执行结果

- **消息**：群聊或私聊收到的内容，用于回复、转发和监控。
- **事件**：例如机器人入群、群改名、通过好友申请成功，用于触发事件任务。
- **执行结果**：已下发指令的成功或失败反馈，用于判断操作有没有完成。
- **在线状态通知**：机器人上线、下线通知，可单独发送到企微群机器人，也可通过事件回调接收 JSON。

收到“群改名事件”不等于某条改名指令成功回执；二者用途不同。

## 三种任务

| 类型 | 触发方式 | 适合用途 |
| --- | --- | --- |
| 指令任务 | 用户立即下发 | 测试、临时发送或群管理 |
| 定时任务 | 到达指定时间 | 每日提醒、周期操作 |
| 事件任务 | 收到匹配的新事件 | 欢迎好友、建群拉人、入群说明 |

事件任务可以包含多个动作，按列表顺序组成指令。顺序执行不代表事务：后续失败不会撤销前面已经完成的动作。

## 名称、备注和上下文

群名称、群备注、联系人名称和联系人备注不是同一字段。消息匹配会优先使用回调提供的备注，再使用名称。任务中引用事件字段时，应选择实际有值的字段；新通过的好友通常没有备注。

轻量上下文按机器人与会话区分，默认最多读取最近 20 条、保留 15 天。名称变动可能影响会话关联；它不是永久知识库，也不保证模型记住所有历史。

## 成功的含义

HTTP 请求成功、任务提交成功、客户端执行成功是三个阶段。看见“已提交”后，可继续用消息 ID 查询执行结果，并核对企微实际页面。避免因为结果尚未返回就重复下发建群等操作。
