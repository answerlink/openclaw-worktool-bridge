# 规则配置

规则用于选择收到消息后使用哪个回复引擎。先在「机器人配置」选择机器人和群聊/私聊场景，再开启回复并维护规则。

## 群里什么时候回复

| 选项 | 行为 |
| --- | --- |
| 符合回复规则就回复 | @ 与非 @ 消息均进入规则判断 |
| 只有 @ 机器人时回复 | 非 @ 消息跳过 |
| 让 AI 判断是否需要回复 | 非 @ 消息先判定，需回复才进入规则；@ 消息直接进入规则 |

“我的同事”名单中的人在群里发言且未 @ 机器人时会被跳过。回复开关关闭后，原有规则保留。

群聊判定引擎与生成答案的回复引擎是两个用途。判定引擎留空时使用平台配置的官方服务；独立部署需要管理员配置该服务，或选择可用引擎。

## 匹配模式

| 模式 | 含义 | 示例 |
| --- | --- | --- |
| 全部匹配 | 不限制该项 | 任意名称或内容 |
| 精准匹配 | 去除首尾空白后完全相同 | `客户服务群` |
| 模糊匹配 | 普通输入按包含文字匹配 | `售后` 匹配“咨询售后问题” |

历史配置中以 `^` 开头或 `$` 结尾的模糊模式表达式按正则处理；普通关键词不需要写正则。

名称匹配采用消息回调提供的群/联系人备注，缺少备注时使用名称。修改备注后，请用实际回调内容核对规则。

## 名称与内容的关系

**当前规则的名称条件与内容条件采用“任一命中”，不是“同时满足”。**

例如名称精准匹配“售后群”，内容精准匹配“退款”：售后群的其他消息，或其他群中的“退款”，都可能命中该规则。任一项选“全部匹配”，该规则就可能参与所有消息的匹配。

因此不要用这两个字段表达“只有指定群里的指定关键词才回复”的双重限制。正式启用前，应测试目标会话与非目标会话各一条消息。

## 多条规则命中时

每条消息选择一条规则，顺序是：

1. 精准命中优先于模糊命中，模糊命中优先于全部匹配。
2. 相同匹配等级下，优先级数字越小越优先。
3. 两者均相同时，较早创建的规则优先。

同一条规则的两项均命中时，取其中较精确的等级。调整排序不能让全部匹配规则压过精准命中规则。

## 默认回复与停用

没有规则命中时，可以使用该场景的默认回复；留空则不回复。它不同于“全部匹配的 AI 规则”，后者仍会调用引擎。

需要暂停自动回复时关闭相应场景开关。消息转发是独立配置，暂停回复不会自动暂停转发。

## 配置后验证

在测试会话中分别发送命中、未命中和非 @ 消息，在[消息监控](/docs/monitoring.html)查看处理状态。若调用的引擎与预期不同，先核对备注、匹配等级和优先级，再检查引擎本身。
