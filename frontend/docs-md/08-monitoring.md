# 消息监控与排障

## 先选对记录

| 要确认的事情 | 查看位置 |
| --- | --- |
| Console 有没有收到聊天消息 | 消息监控的消息记录 |
| 有没有收到群改名、好友申请等事件 | 消息监控 → 事件记录 |
| 事件是否触发自动化 | 事件任务的运行记录 |
| 指令是否被客户端执行 | 指令任务查询 |
| 转发是否命中与提交 | 消息转发的日志 |
| 定时任务是否到期运行 | 定时任务的运行记录 |

事件任务列表为空只是没有配置任务，不代表事件记录为空。

## 一条消息的排查顺序

1. **没记录**：检查机器人 ID、在线情况、回调开关与接收地址，确认消息确实由客户端读取并上报。
2. **有记录但跳过**：检查群聊/私聊开关、@ 策略、同事名单、AI 是否判定无需回复。
3. **引擎不符合预期**：核对名称或备注、规则的任一命中逻辑、精准/模糊匹配等级和排序。
4. **引擎调用失败**：查看错误原因与耗时，检查服务地址、凭证和第三方响应。
5. **已提交但手机没发出**：查看指令任务查询中的客户端结果与错误原因。

消息监控里的本地记录 ID 不一定是下发指令的 messageId；查询指令时使用对应下发结果中的消息 ID。

## 事件没有触发动作

先检查事件记录：事件名称和字段是否与任务匹配。再检查任务启用状态、过滤条件、冷却时间及变量是否有值。只有保存并启用后收到的新事件才触发任务，历史事件不自动重放。

出现“已提交”表示动作已交给 WorkTool；失败、跳过或结果未知请查看运行详情。不要直接重复触发建群来判断是否恢复。

## 查询范围与保留时间

消息监控与收发日志默认保留 15 天，事件记录保留 30 天。指令任务查询当前面向最近 2 天、最多 2000 条指令，不是永久指令档案。独立部署的日志保留可由管理员调整。

指令的“待执行”可能只是尚未取得明确结果；“已终止”也不代表撤销了已经完成的操作。[指令下发与查询](/docs/command-tasks.html)说明了取消边界。

## 提供排查信息

向管理员反馈时提供机器人 ID、发生时间（含时区）、会话名称或备注、具体动作、messageId（如有）以及相关错误记录。管理员可使用「机器人排查」及客户端日志功能进一步核对。

不要在公开截图中展示回调签名、API Token 或密码。
