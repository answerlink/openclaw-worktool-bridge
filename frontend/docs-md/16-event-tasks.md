# 事件任务

事件任务在收到指定的新事件后执行动作，例如通过好友申请后发送欢迎语、创建群并拉入该联系人。

## 支持的触发事件

| 事件 | 含义 |
| --- | --- |
| 机器人入群 | 机器人进入一个群，不是群里任意成员加入 |
| 群名称变更 | 收到群改名事件 |
| 群解散 | 收到群被解散事件 |
| 机器人被移出群 | 收到机器人被移出事件 |
| 通过好友申请成功回调 | 客户端成功通过好友申请 |
| 机器人上线、下线 | 收到在线状态 JSON 事件 |

先在「机器人信息」将事件回调接入 Console，再到「消息监控 → 事件记录」确认接收。只有新收到的匹配事件会触发已启用任务，历史记录不自动重放。

## 创建任务

1. 选择机器人，填写任务名称和触发事件。
2. 按需设置筛选字段与包含文字，留空表示不按该文字限制。
3. 添加动作，填写目标、内容或群操作参数。
4. 检查顺序、冷却设置和启用状态，保存。

事件任务支持最多 10 个动作，可用箭头调整上下顺序。

## 动作和目标

| 动作 | 可配置内容 |
| --- | --- |
| 发送文本 | 目标、内容 |
| 发送图片或文件 | 文件名、HTTP(S) 下载地址、类型、附带文本消息 |
| 创建外部群 | 新群名、成员、群备注等；好友事件可拉入事件联系人 |
| 修改群 | 改名、公告、拉入成员、备注等 |

可发送到事件中的群或联系人，也可指定固定目标。群已解散、机器人被移出群、上线下线等场景需指定仍可访问的固定目标。

「附带文本消息（可选）」留空时只发文件；图片类型填 `image`，一般文件可保留 `*`。下载地址使用实际 URL，不支持在 URL 中插入事件变量。

## 插入变量与日期

使用字段旁按钮插入变量，触发时替换成实际值：

| 变量 | 来源 |
| --- | --- |
| `{{groupName}}` | 事件中的群名称 |
| `{{groupRemark}}` | 事件中的群备注 |
| `{{friendName}}` | 事件中的联系人名称 |
| `{{friendRemark}}` | 事件中的联系人备注 |
| `{{currentDate}}` | Console 接收事件时的北京时间日期，如 `20261020` |

不同事件只提供相关变量。日期在接收时固定，延迟执行跨过午夜也不会变成第二天。

新通过的好友通常没有备注，优先使用联系人名称。被引用的变量缺失或为空时，该次任务会失败，不会拿空名称继续下发。不要无条件把联系人备注、群备注拼进必填字段。

## 示例：通过好友申请后建群并欢迎

选择「通过好友申请成功回调」，按顺序配置：

1. 创建外部群：群名填写 `{{friendName}}服务群{{currentDate}}`，开启拉入事件联系人，按需补充其他成员。
2. 发送文本：固定目标填写同样的 `{{friendName}}服务群{{currentDate}}`，内容填写欢迎语。
3. 如需发送资料，再添加图片或文件动作，并填写附带文本消息。

同一次触发的日期相同，因此群名模板可重复引用。第二步按名称寻找群，不是绑定第一步返回的群 ID；重复群名或建群失败时仍可能导致后续失败。

## 顺序、冷却与重复事件

所有动作会先解析并验证，再按顺序组成一条指令的 list 下发。它不是事务，也没有“前一步失败则回滚”的保证。涉及新建群时，应检查每一步执行结果。

默认冷却 60 秒，可选按联系人/群分别冷却或整个任务冷却，范围为 10～86400 秒。冷却用于减少重复触发，不是严格业务去重；名称变更也可能影响分组。

平台会按事件标识去重，没有标识时对短时间相同内容做尽力去重。同一机器人由多个账号分别创建任务，可能分别执行；配置前与共同管理者确认。

## 运行记录

| 状态 | 含义 |
| --- | --- |
| 排队、运行中 | 等待调度或正在处理 |
| 已提交 | WorkTool 已接受，继续查客户端执行结果 |
| 失败 | 参数、变量或提交等出现错误，查看详情 |
| 已跳过 | 冷却、任务状态或过期等原因未执行 |
| 结果未知 | 无法安全确认是否已提交，不自动重发 |

排队超过 10 分钟会跳过；运行中超过 5 分钟会标记结果未知。修改、停用或删除任务会取消尚在排队的运行，已开始的操作不保证撤销。

任务列表不是事件接收日志。排查请先看[消息监控](/docs/monitoring.html)，再看本页运行记录，最后核对[指令结果](/docs/command-tasks.html)。
